### Промпт для Claude Code: Разработка OPC UA SendBox

**Роль:** Ты — senior Python-разработчик и инженер по автоматизации. Твоя задача — с нуля спроектировать и реализовать веб-сервис **OPC UA SendBox** для экосистемы **Electroman**.

#### 1. Контекст и преемственность (Критически важно)
Изучи существующие проекты, чтобы новый сервис стал их логичным продолжением:
*   **ModbusToolkit** (`modbustoolkit.electroman.by`): Десктопный «швейцарский нож» инженера-наладчика с 19 инструментами, бесплатный, с русским и английским интерфейсом.
*   **Modbus SendBox** (`modbus-sendbox.electroman.by`): Публичная онлайн-песочница для быстрой проверки Modbus-подключений без оборудования.
*   **OPC UA SendBox** должен стать **веб-аналогом SendBox**, но для стека OPC UA. Это многопользовательская песочница, где инженер может поднять виртуальный OPC UA сервер, сгенерировать теги (синусоида, случайные числа, алармы) и проверить подключение своего клиента (SCADA, HMI, UaExpert) через браузер.

#### 2. Технический стек и архитектура
*   **Язык и фреймворк:** Python 3.11+.
*   **Бэкенд:** **FastAPI** (для REST API управления сессиями и WebSocket для live-логов/статуса).
*   **Ядро OPC UA:** Библиотека **`asyncua`** (современная, асинхронная, хорошо работает с FastAPI event loop).
*   **Многопользовательский режим:** Каждый пользователь (сессия) должен получать **изолированный экземпляр OPC UA сервера** (или изолированное адресное пространство), работающий на уникальном порту (например, динамический диапазон 4840–5000).
*   **Состояние:** In-memory хранилище (dict) с блокировками (`asyncio.Lock` или `threading.Lock` для синхронных участков) для реестра активных сессий и портов.

#### 3. Функциональные требования (MVP)
1.  **Создание сессии:** Эндпоинт `POST /api/sessions` создаёт новый OPC UA сервер, возвращает `session_id`, `endpoint_url` (например, `opc.tcp://host:port/electroman/`) и `web_ui_url` для управления.
2.  **Генерация тегов:** Возможность через API или UI добавить теги (синусоида, пила, случайное число, константа) с настраиваемым периодом обновления.
3.  **Симуляция алармов:** Генерация событий `Alarm & Condition` по расписанию или вручную (для тестирования реакции SCADA).
4.  **Управление жизненным циклом:** `DELETE /api/sessions/{id}` должен корректно останавливать OPC UA сервер и освобождать порт.
5.  **Таймаут:** Автоматическая остановка простаивающих сессий (например, через 30 минут).

#### 4. Безопасность и многопоточность (Особое внимание)
*   **Потокобезопасность (Thread Safety):** Поскольку `asyncua` работает в event loop, а управление сессиями может затрагивать синхронные участки (например, запуск сервера в отдельном процессе/потоке), необходимо предусмотреть **механизмы блокировки** при доступе к общему реестру портов и сессий. Используй `asyncio.Lock` для асинхронных операций и `threading.RLock` для синхронных.
*   **Изоляция:** Ошибка или зависание сервера одного пользователя не должны влиять на других. Рассмотри возможность запуска каждого OPC UA сервера в отдельном **процессе** (`multiprocessing`) или хотя бы в изолированной задаче (`asyncio.Task`), чтобы падение одного не убивало весь FastAPI-воркер.
*   **Аутентификация:** Базовая аутентификация для пользователей (можно использовать JWT или простые API-ключи), чтобы ограничить количество активных сессий на пользователя.

#### 5. Тестирование (Обязательное условие)
Напиши **полный набор тестов** с использованием `pytest` и `pytest-asyncio`.
*   **Unit-тесты:** Тестирование логики генерации тегов (правильность синусоиды, границы случайных чисел), валидации входных данных API.
*   **Интеграционные тесты (с моками и реальным сервером):**
    *   Запусти реальный in-process `asyncua.Server` в фикстуре (как показано в примерах сообщества).
    *   Напиши тест-клиент, который подключается к созданному через API серверу, читает тег и проверяет, что значение обновляется.
    *   **Тест на многопользовательский режим:** Создай две сессии параллельно, подключись к обеим, убедись, что данные не пересекаются и порты разные.
*   **Тест на устойчивость (Thread Safety):** Запусти 10 параллельных задач на создание/удаление сессий и убедись, что не возникает `race condition` (например, двум сессиям не достался один порт).
