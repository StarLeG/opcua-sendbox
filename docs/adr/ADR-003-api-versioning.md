# ADR-003 · Версионирование REST API и capabilities-эндпоинт

- **Статус:** принято
- **Дата:** 2026-11-03
- **Задача:** TASK-204

## Контекст

План интеграции ModbusToolkit (`Doc/plans/2026-11-03-opcua-sendbox-integration.md`)
требует от SendBox версионированный контракт и capabilities-эндпоинт **до этапа 2**:
приложение должно «деградировать честно» — знать версию сервиса и его возможности,
а не угадывать их из ошибок. Контракт публичный, но потребителей ещё нет:
ModbusToolkit интеграцию не начинал, UI и README используют неверсионированные пути.

## Решения

1. **Двойной префикс.** Единый `APIRouter` монтируется дважды: на `/api/v1/...`
   (канонический контракт, попадает в OpenAPI) и на `/api/...` (совместимый алиас,
   `include_in_schema=False`). Ничего не ломается: UI, README-примеры и curl-скрипты
   продолжают работать, новый потребитель получает контракт с версией. Swagger
   документирует только `/api/v1/...`, чтобы список операций не дублировался.

2. **Версия контракта — целое число** `api_version` в capabilities, сейчас `1`.
   Несовместимое изменение контракта — новый префикс `/api/v2/...`, старый остаётся
   и объявляется deprecated в capabilities. Добавление новых полей в ответы и новых
   эндпоинтов — совместимо: клиенты обязаны игнорировать незнакомые поля.

3. **`GET /api/capabilities` (и `/api/v1/capabilities`)** — машиночитаемый ответ:

   - `service` — имя сервиса (`opcua-sendbox`);
   - `version` — версия сервиса (SemVer из `importlib.metadata`, тот же источник,
     что в `/healthz`);
   - `api_version` — версия контракта REST API;
   - `features` — **только поддерживаемые** возможности: `shared_server`,
     `personal_sessions`, `tag_write`, `history`, `alarms`, `alarm_trigger`,
     `security_none`. Отсутствие фичи в списке означает, что её нет (Ack/Confirm,
     шифрование, логин/пароль — не перечисляются);
   - `limits` — лимиты песочницы из `Config`: `sessions_per_key`, `sessions_per_ip`,
     `sessions_total`, `tags_per_session`, `alarms_per_session`, `idle_timeout_s`,
     `max_lifetime_s`.

4. **Служебные эндпоинты** `/healthz` и `/metrics` не версионируются: это контракт
   инфраструктуры, не API песочницы.

## Последствия

- Контракт `/api/v1/...` готов к согласованию с планом ModbusToolkit (этап 2).
- OpenAPI читается как «официальный» контракт; алиас `/api/...` живёт бессрочно
  до явного решения снять его (для 0.x это не реверсируемое обещание — см. ниже).
- Каждое новое поле в `capabilities` — совместимое изменение; новые фичи появляются
  в списке по мере реализации.
- До `1.0.0` контракт формально не закреплён (ветка 0.x): несовместимое изменение
  поднимает MINOR по правилам SemVer, но правило «старый префикс остаётся»
  соблюдается уже сейчас, чтобы потребителям не приходилось догонять.
